# ENVELOPE 2026-08-26 — explorer v8 (live SearchCore graft) safety case

Law #3 artefact for build stage 7. Everything below is measured or arithmetic;
nothing is projected from intuition.

Code: `submission/_explorer_v8/graft_explorer_v8.py`
Tests: `submission/_explorer_v8/test_graft_explorer_v8.py` (48 tests, all offline)
Substrate: `submission/_explorer_floor/graft_explorer.py` (v7, flown live at 1.51)

## 0. The claim

**v8's run envelope is a strict subset of v7's flown envelope.** v7 flew the
scored box at 1.51 with a 45-minute cumulative grind cap, 600 s/1500 s
per-engagement caps, a run-wide semaphore of 1 and an 18000 s start cutoff.
v8 keeps every one of those knobs at its v7 default, adds two guards v7 did
not have, converts entry-time polling into per-action enforcement, and caps
every new mechanism explicitly. No knob is loosened.

The 08-20 precedent (sub 55634118, killed at the 9 h wall) was an
**unbounded** grinder. The v2 arm completed the envelope with unbounded 20-min
grinds; 2700 s cumulative is inside empirically-proven-safe territory.

## 1. The box

| quantity | value | source |
|---|---|---|
| scored games | 110 | run geometry |
| worker concurrency | 28 | run geometry |
| waves | `ceil(110/28)` = 4 | arithmetic |
| nominal per-game slot | 7920 s | run geometry |
| nominal run wall | `4 x 7920` = 31680 s = 8.80 h | arithmetic |
| hard box | 32400 s = 9.00 h | Kaggle |
| nominal slack | 720 s | 32400 − 31680 |

The nominal 720 s slack is *not* what funds grinding. Grinding is funded by
**early finishes**: a game that completes before its slot expires returns its
worker, and the grinder only ever engages games that have already stalled
(v7 trigger: ≥120 scored actions or ≥10 LLM turns on one level with zero
completions this run). A stalled game is by construction not going to use its
remaining slot productively.

## 5. Does the 9 h box still close?

Worst case, in full:

```
grind wall added to the run          <= 2700 s + 0.25 s        (guard #5)
                                     serialized by the semaphore (guard #1)
last grind action                    <= 19500 s = 5.42 h        (guard #7)
remaining wall after last grind      >= 32400 - 19500 = 12900 s = 3.58 h
per-game delay from grinding         <= 1500 s of that game's 7920 s slot
                                     and only on a game already stalled
grind blocked when the game's own
soft time is under 120 s / aborted
under 60 s                                                      (guard #10)
```

Two independent reasons the box closes:

1. **Subset argument (primary).** v7 flew this exact envelope live and
   completed the run (draw 1.51). v8 does not loosen a single knob; it tightens
   guard #5 from a 4200 s worst case to 2700 s and turns guard #7 from implicit
   to enforced. If v7's envelope closed, v8's does.
2. **Arithmetic argument.** 2700 s of serialized grind against 720 s of nominal
   slack requires ~1980 s of early-finish slack across a 4-wave, 110-game run
   — 18 s per game, or equivalently 2.4 % of one wave. Grinding only engages
   stalled games, whose slots are otherwise spent on unproductive LLM turns.

**Explicit residual risk.** The arithmetic argument depends on early-finish
slack we have not re-measured this session; the subset argument does not. If a
smoke shows wall pressure, the single knob to turn is
`EXPLORER_RUN_GRIND_BUDGET_S` (2700 → 1200), which costs at most one
tu93-class crack and nothing on the ft09 class.

# ADDENDUM — v8.1 early specialist probe (2026-08-26, after smoke #1)

## A1. Why the graft changed

Smoke #1 (kernel `arc3-v8-smoke` v1, RTX Pro 6000, 4 h box) was a **null
read**, and the cause is a design flaw in the *trigger*, not in the search:

| observation (v1, first-hand) | value |
|---|---|
| ft09 LLM actions in a 3600 s box | **17** |
| ft09 levels completed by the LLM | 2 / 6 |
| ft09 harness score | 14.29 (= the completion-share cap `3/21 x 100`) |
| grinder engagements | **0** |
| grinder engine actions | **0** |
| envelope maxima observed | all 0.0 |

v7's trigger arms on **120 scored actions or 10 LLM turns on ONE
never-completed level**. A game that spends an hour on 17 actions never
reaches either threshold, and a game the LLM completes levels on is blocked
outright by the self-harm gate. So the specialist tier — **1.6 s to detect,
9.5 s to crack ft09, ~100 projected after banking** — was never consulted.
Gating *detection* behind a soak wastes it.

## A2. What was added

`early_specialist_probe(session)` runs `specialists.detect` **once per game,
right after warmup, with no stall precondition**, and takes the engagement
immediately on a hit. Generic search is unchanged: still behind the stall
trigger.

| new guard | value | enforced at |
|---|---|---|
| probe concurrency, run-wide | `BoundedSemaphore(2)` (`EXPLORER_V8_EARLY_CONCURRENCY`) — separate from the grind gate, which stays at 1 | `_PROBE_GATE`, non-blocking |
| probe engine actions | **800** (`EXPLORER_V8_EARLY_PROBE_ACTIONS`); measured need 89-187 | `GuardedEnv` |
| probe wall | **120 s** (`EXPLORER_V8_EARLY_PROBE_S`) | `GuardedEnv` |
| probe wall counted against the cumulative run budget | yes — added to `_GRIND_WALL_SPENT` in a `finally` | `early_specialist_probe` |
| every run-level guard (run cutoff, cumulative budget, soft time, runtime cap, per-game action cap, stop event) | re-checked before the probe spends anything | `early_specialist_probe` |
| engagement after a hit | the **unchanged** 600/1500 s + 292 500-action caps, main grind gate held, `grinds_per_level` incremented | `_engage` |
| probes per game | 1 | `xs["v8_early_done"]` |

The engagement's `t0` stays at the *probe's* start, so the probe's wall is
charged to the engagement, never the other way round.

## A3. The self-harm window — and the tax, measured

Probe actions are billed by the server card to the level they land on, so on a
game with **no** specialist they are a tax on level 1's `(b/a)^2`. Two
conditions bound the blast radius:

* the level must be untouched — `session.action_count <= 24`
  (`EXPLORER_V8_EARLY_MAX_ACTIONS`; wide enough to survive gate contention when
  28 workers start at once, small enough to stay cheap), and
* the LLM must have completed **no** level — past that, `bank_crack` would
  decline anyway ("plan does not start at level 1"), so the upside is gone
  while the tax would remain.

Measured probe cost (`test_I_probe_cost_is_bounded_and_measured`, real engine):

| game | probe actions | live cost @130 act/s | detected |
|---|---|---|---|
| ft09 | **89** | 0.7 s | `ft09_gf2` |
| cn04 | 113 | 0.9 s | — |
| sk48 | 135 | 1.0 s | — |
| vc33 | 179 | 1.4 s | — |
| dc22 | 187 | 1.4 s | — |

Wall cost is negligible (≤1.4 s inside a 2700 s budget). The **score** cost is
not, and is stated plainly: on a game whose only completion is a cheap level 1,
adding ~150 actions to level 1 collapses that level's efficiency term. Worked
example on ft09's real baselines `[43, 12, 23, 28, 65, 37]` (total weights 21):
an L1-only completion in 9 actions is worth `115/21 = 4.76`; with 89 probe
actions billed it is worth `(43/98)^2 x 100 / 21 = 0.92`. **Tax ≈ 3.8 points on
that game.**

Against that: ft09 cracked and banked projects **100.0** (verified offline
end-to-end: 6/6 levels, 1233 engine actions, 75-action replay) versus the
14.29 its LLM actually banked live — **+85.7 on one game**. The trade is
positive whenever the detection hit rate exceeds ~4 %; the dev-25 rate is
4/25 = 16 %. The hidden-set rate is unknown and is the real uncertainty —
which is why smoke #2 reports the probe's per-game action count and the
tax-adjusted score projection for every game, not just the crack.

Knob if the live read says the tax is not paying for itself:
`EXPLORER_V8_EARLY=0` restores v8.0 exactly (detection behind the stall
trigger); `EXPLORER_V8_EARLY_ENGAGE=0` keeps detection as a pure diagnostic.

## A4. Stop-after-crack

A cracked+banked game sets `xs["v8_stop_game"]`, and the session's
`should_stop` then returns True (`EXPLORER_V8_STOP_AFTER_CRACK`, default on).
Rationale: after banking, the engine sits on the fresh post-WIN play; further
LLM actions can only add actions to a play whose levels are already recorded,
and they hold a worker the next wave needs. Fail-open: the seam is
presence-gated at install and the flag disables it.

## A5. Test coverage

61 offline tests pass (48 pre-existing + 13 new `test_I_*`): detection at
warmup, detection with the stall trigger provably unarmed, installed-poll
ordering, end-to-end early crack **and** bank on ft09, each envelope guard on
the early path (probe action cap, cumulative budget, run cutoff, soft-time
floor, per-game action cap), the self-harm window, once-per-game, flags-off
parity (`EXPLORER_V8=0` and `EXPLORER_V8_EARLY=0` both leave v7's poll
untouched), and the probe-cost measurement above.

# ADDENDUM 2 — the scoring seam, measured on the competition server (2026-08-27)

## B1. The question smoke #2 forced

Smoke #2 cracked ft09 (6/6 levels, banked 75-action replay) and its run
summary said `state=gave_up level=0/6 score=0.00`. Two accountings exist and
they disagree:

| | what it counts | where |
|---|---|---|
| framework mirror | ONLY actions passed through `Game.execute_action` | `taaf/game.py:497-573`, scored by `GameRun._compute_final_score` (`game.py:381-413`) |
| **engine scorecard** | **every step through `game.env`**, grinder included, **max over plays** | attached at `taaf/game_api.py:204` — `arcade.make(..., scorecard_id=...)` |

The grinder drives `game.env` directly (`GuardedEnv.step/reset`), so the mirror
cannot see a grinder win. The framework says so itself — smoke #2's log:

```
R11.12: score mismatch for ft09-0d8bbf25: framework=0.0000, engine=100.0000
```

(`_finish_game`, `taaf/game_api.py:264-292`.) **The mirror is a diagnostic; the
engine card is the score.** Smoke #2's report displayed the mirror, which is
why bar 2 was graded on a number that never pays.

## B2. Proof on `taaf.competition_arcade.CompetitionArcadeServer`

The real `arc_agi.server.create_app(competition_mode=True)` REST app —
`submission/_explorer_v8/test_competition_scoring.py`:

| test | result |
|---|---|
| ft09 specialist crack, engine card | **score 100.0**, levels 6/6, `completed=True`, actions 1308, resets 323, **2 plays**: `play[0]` (search) **3.51**, `play[1]` (banked 75-action replay) **100.0** |
| the same run's framework mirror | 0.0, levels 0, actions 0 |

The environment row's score is the **max over plays**. Reading `runs[0]`
reads the search play — that is what 3.51 is. Banking works because a post-WIN
RESET is the one reset the competition guard does **not** swallow
(`api.py:316-334` swallows only `_action_count == 0`), so it opens a fresh play.

## B3. The probe tax, measured instead of modelled

A/B on the same server: declined 89-action probe, then ft09's minimal 4-action
level-1 plan through the **scored** path, versus the same plan with no probe.

| arm | engine score | plays |
|---|---|---|
| control | **4.7619** | 1 |
| after an 89-action probe | **0.9965** | 1 |
| after 1000 grind actions | **0.0087** | 1 |

Tax = **3.77 points**, matching the billed-together prediction
`(43/93)^2 x 100 / 21 = 1.02` to 2 %. Break-even detection rate
`p* = 3.77 / (85.7 + 3.77) = 4.2 %`, inside the pre-registered 15 % kill line.

**Offline cannot see this.** Without the competition guard, a reset at
`action_count == 0` performs a full reset and opens a fresh play, so offline
max-over-plays isolates grind actions and the tax reads ~0 (smoke #2 emitted an
R11.12 mismatch for ft09 only). Any tax read must come from the competition
server; the offline engine card is valid for the crack/bank path (100.0 on
both) and invalid for the tax.

## B4. Consequence for the generic stall grind

Only a post-WIN reset opens a play. A grind that unlocks levels but does **not**
crack therefore shares one play with everything the LLM does afterwards, and
every one of its actions is charged to the level the LLM later completes —
1000 actions already collapse a level-1 completion from 4.76 to 0.0087, and
smoke #2's dc22/sk48 engagements spent **292 687 / 292 635**. Offline this is
invisible (dc22 reported 4.76 with 2 levels); live it would be ~0.

The value case therefore rests entirely on **cracks that bank**. A generic
engagement that cannot finish the game is, in the scored accounting, at best
neutral (it only engages games with no LLM completion, whose score is already
0) and negative whenever the LLM would have completed a level afterwards.
Knob: `EXPLORER_V8_EARLY_ENGAGE=1` with the stall path disabled restricts
engagement to specialist hits, which is where the measured cracks are.

# ADDENDUM 3 — failed-engagement cost, the flight config, and the v7 retro (2026-08-27)

## C1. What a NON-cracking engagement costs (measured)

`submission/_explorer_v8/measure_failed_engagement.py`, on
`CompetitionArcadeServer`. ft09, minimal plans for levels 1-3 (`[4, 7, 14]`
against baselines `[43, 12, 23]`), N wasted actions injected either before
level 1 or after levels 1-2 are already done. Control = **28.5714**.

| failure lands on | N=2 000 | N=10 000 | N=50 000 | N=292 500 |
|---|---|---|---|---|
| level 1 | **−1.19** | −1.19 | −1.19 | −1.19 |
| level 3 | **−12.14** | −12.14 | −12.14 | −12.14 |

N=2 000 and N=10 000 are measured; the closed form reproduces both **exactly**,
so the last two columns are arithmetic. Two conclusions:

1. **The cost is a step function.** By ~2 000 actions the `(baseline/actions)²`
   term is already ~0; 292 500 costs exactly what 2 000 costs. A tighter action
   cap therefore does **not** buy back score.
2. **The level dominates.** Failing on level 3 costs **10×** failing on level 1
   — its weight is 3, and losing it moves the completion-share cap too. The
   `100/W` bound in Addendum 2 §A3 protects only the level-1 case.

## C4. Expected value, against the measured numbers

Per game, `p` = frequency of a **cracking** specialist class in the hidden set:

```
EV(p) = p x GAIN - (1-p) x C_probe          [crack-or-nothing: no failure term]
GAIN    = +85.7   (ft09 14.29 -> 100.0, measured; +100 on a game scoring 0)
C_probe = 2.7 - 3.8   (measured: -3.77 with 1 level completed, -1.19 with 3)
```

| config | EV / game | note |
|---|---|---|
| A. v8.1 as smoked (engage every detection, stall on) | `0.04x85.7 − 0.12x12.14 − 2.7` = **−0.73** | negative: 3 of 4 detectors fail high |
| B. **crack-or-nothing (proposed)** | `0.04x85.7 − 2.7` = **+0.73** | +3.43 gain, −2.7 probe tax |
| C. detect-only | **−2.7** | diagnostic value only |
| D. v8 off (v7 lane) | ≤ 0 | see C5 |

**Break-even p = C_probe / (GAIN + C_probe) = 3.1 % (at 2.7) to 4.2 % (at 3.8).**

**The only estimate of p we have is the dev corpus: ft09_gf2 fires on 1 of 25
games = 4.0 %** — which straddles break-even. Config B's EV is therefore
**≈ 0 ± 1 point per game on our own data**, and its sign depends on a
hidden-set frequency we cannot measure. (All four classes together fire on
4/25 = 16 %, but only the ft09 class converts, so 16 % is not the number that
pays.)

The dominant term is the probe tax on the ~96 % of games that never crack, and
it is **structural**: the double-reset that would isolate the probe into its
own play is exactly the reset the competition guard swallows
(`api.py:316-334`). The highest-value next build is therefore a **cheaper
probe** — a zero-action frame pre-screen before the 43-action warmup + 45-action
detect. At C_probe ≈ 0 the EV becomes +3.43/game at the same p.

## C5. Retro — was v7 penalising its own live draws?

v7's own logs, pulled from the kernels that flew (`arc3-duck38-v12-xpl`,
`arc3-duck38-v12-xd`):

```
[explorer] dc22: engaging on level 1 — grind-to-win, budget 500000/600s
[explorer] dc22: level 1 UNLOCKED (20 actions minimal, 14482 spent)
[explorer] dc22: grind ended (frontier_exhausted) after 174429 actions, 1 unlock
[explorer] dc22: engaging on level 2 ... ended after 159972 actions, 1 unlock total
[explorer] sb26: ... after 1648 actions, 0 unlocks
```

So v7 **did** engage, spent **334 401 actions on dc22 across two engagements**,
and never cracked. Both smokes then reported `dc22 score=4.76, levels=1` — the
completion-share cap for one level. That 4.76 is an **offline artifact**: the
level was unlocked by the grinder at 14 482 actions, so on the competition
accounting the same play scores `(59/14482)² x 100 / 21 ≈ 0.0008`.

**Verdict: yes, in kind — v7's partial grinding converts a level it unlocks
into a level worth ~0, and any level the LLM completes afterwards in the same
play carries the grind's actions.** Bounded in magnitude: grinding is
serialized by the semaphore and capped cumulatively (2 700 s, worst case 4 200 s
under v7's entry-only check ≈ 546 k actions at 130 act/s), so at most ~3
dc22-sized engagements per run, each costing ≤ ~12 points on one game — an
upper bound of **~0.3 LB points** across 110 games. That is inside the base
band (sd 0.21) and does not invalidate the 1.33 / 1.51 draws, but it does mean
**those draws were slightly depressed, not inflated, by the explorer** — and
that the explorer lineage has never had a positive scored contribution
demonstrated. The first one available is a banked crack.
