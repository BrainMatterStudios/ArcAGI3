# BET 3 — SCOPE & DESIGN (held-out-family in-context inference probe) — 2026-06-28

Pre-build scoping per user request ("read synthgen, write design + pre-registered kill thresholds, sign-off, then build").

## SCOPING FINDING 1 — the handoff over-promised the generator
The handoff says "USE THE EXISTING synthgen generator." **It is not reusable as an engine.**
`synthgen/{genres,canvas}.py` is a **static frame generator for a genre CLASSIFIER** (the Genre-Perceiver
program): `generate_one(rng, genre)` returns a single labelled 64×64 frame. There is **no `step(action)→
next_frame`, no mechanic dynamics, no reward / level-up logic**. Only two things are genuinely reusable:
- `canvas.roles(rng, k)` — the colour-agnostic role randomization (the load-bearing "zero surface signal" lever).
- a few drawing primitives (`place_avatar`, `place_block`, `scatter_items`, `place_bordered_square`,
  `solid_interior`) to render frames.
**Everything else — the interactive engine, the mechanic families' transition functions, the win
conditions, and the learner — must be built.** The "1–1.5 day" estimate in the handoff assumed an engine
that does not exist.

## SCOPING FINDING 2 — a validity trap: imitation ≠ inference
The plan's hypothesis is "in-context **inference** can't generalize across mechanic families." A cheap
behaviour-clone-from-oracle (train a GRU to imitate per-family solving policies, test on a held-out family)
would **falsely KILL**: a model that only imitates REACH/COLLECT/GATE oracles, shown PUSH at test, cannot
invent PUSH's solution — pure imitation can't produce an unseen mechanic's actions regardless of whether
the mechanic is *inferable*. So BC tests the wrong thing. A valid probe must test whether the **interaction
history (frame, action, frame-change) is informative about the held-out mechanic** — i.e. within-episode
adaptation, not cross-family imitation. This forces either RL² (finicky, needs a T4) or a supervised
in-context inference probe (cheap, stable, and still valid). I recommend the latter FIRST.

## PROPOSED BUILD (staged, cheapest-decisive-first — mirrors BET 2's oracle-before-model discipline)

### Minimal interactive engine (`synthgen/engine.py`, new)
Deterministic 64×64 gridworld. State = (grid, avatar cell, hidden mechanic state). Actions map to the SDK
6: {up,down,left,right} = ACTION1-4 (avatar moves 1 cell, blocked by walls), click(x,y)=ACTION6, noop.
`step(action) → (frame, reward, done)`; `reward=1` (level-up) on the family's win condition. Frames render
via `canvas` primitives. **Every role colour randomized per episode via `roles()`**; layouts randomized.

### 4 structurally-distinct mechanic families (transition + reward differ, not just appearance)
1. **REACH** — move avatar onto the target cell. (movement + goal-contact)
2. **COLLECT** — move avatar over all N scattered items; win when set empty. (movement + set-completion)
3. **GATE** — a switch cell must be touched/clicked first (opens the gate), THEN reach the target; reaching
   before the switch does nothing. (ordered subgoal / state-dependent affordance — the key W1-style case)
4. **PUSH** — push a block onto a marker (sokoban dynamics). (contact-push transition)
Leave-one-mechanic-family-out: train on 3, test on the never-seen 4th. Roles randomized so "which colour is
the avatar/switch/target" carries zero signal — the family must be read from interaction dynamics alone.

### STAGE 0 (recommended Day-1 kill-test, CPU-OK, ~1 day) — supervised in-context inference probe
Roll out a random/exploratory policy on each family → trajectories of (frame, action, frame-change). Train a
small in-context model (GRU or tiny transformer over the trajectory) to predict **the rewarding-action class
for the current state** (a supervised label the engine knows). **Leave-one-family-out.** Measure held-out-
family prediction skill vs chance. This directly answers "is the mechanic inferable from interaction history
across families" without any RL instability — and is a valid INFERENCE test (not imitation).
- **Pre-registered KILL:** held-out-family rewarding-action prediction AUC **< 0.55** (≈ chance; mirrors the
  CNN LOGO-AUC 0.457 offline-goal-ID wall). → W1-strong confirmed, meta-RL hypothesis class closed, no Stage 1.
- **Pre-registered PROCEED:** AUC **> 0.70** with a clean margin on the held-out family across ≥3 of the 4
  leave-one-out folds → build Stage 1.
- **GREY (0.55–0.70):** report; do not spend on Stage 1 without a second look.

### STAGE 1 (ONLY if Stage 0 clears, ~2–3 days + T4) — RL² level-up-rate probe
RL² GRU policy (obs encoder → GRU over (obs, prev_action, prev_reward) → policy head), meta-trained with
PPO-lite across the 3 training families, roles+layout randomized. Run on the held-out family; measure:
- (a) **held-out-family level-up rate vs a random policy** (the plan's primary number), and
- (b) **actions-to-levelup vs the 35× RHAE headroom** (`scripts/rhae_headroom.py`).
- **KILL:** held-out level-up rate ≈ random. **PROCEED to leave-one-REAL-game-out:** clear margin over random.

## HONEST COST / RISK (revising the handoff)
- **Stage 0 alone ≈ 1 day**, CPU-fine, decisive on its own (settles W1 weak-vs-strong validly and cheaply).
- **Full bet through Stage 1 ≈ 3–4 days + a T4**, not the handoff's 1–1.5 days.
- **Prior (carried from the plan):** odds-on this confirms W1-strong and joins the graveyard — which is still
  valuable (definitively closes the meta-RL hypothesis class). EV-toward-*winning* is low; EV-toward-*knowing*
  is high. It does not touch the banked 0.33 (analysis-only, firewall trivially intact — no submission path).
- **Design risk to watch:** families must be genuinely distinct in *dynamics* (not renderable apart from a
  single frame), or Stage 0 could pass on leaked static structure = false PROCEED. Mitigation: verify a
  single-frame classifier CANNOT separate held-out family above chance (only the *interaction* history can).

## RECOMMENDATION
Build **Stage 0 only** now (1 day, CPU, valid, decisive). Gate Stage 1 (and its T4 spend) on Stage 0 clearing
>0.70. This keeps the whole BET 3 question answerable within ~1 day if W1-strong holds (the likely outcome),
and only escalates to the multi-day RL² build if the cheap probe shows real signal.
