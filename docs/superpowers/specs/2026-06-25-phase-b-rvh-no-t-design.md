## 1. Context

The current research branch, `WinningExplorer`, improves mechanic induction but still fails the
real holdout gate. Two direct measurements from the resumed session matter:

- `ls20`: `transfer=0`, `winning=0` at budget 3000
- `re86`: `transfer=0`, `winning=0` at budget 1500

The branch's own gate therefore fails:

> `GO-RULE ... FAIL — ship transfer-dense`

That evidence closes this line as a **submission candidate**. It does **not** invalidate the
mechanic work as research; it localizes the remaining failure to the goal / terminal layer.

We therefore stop trying to squeeze more score from `WinningExplorer` and move to the judged
Phase B path that has the best cost / ceiling trade-off: **Reward-Value Hybrid, No-T variant**
(`RVH No-T`).

## 2. Decision

Proceed with **RVH No-T**, not Dreamer-first and not more terminal heuristics on
`WinningExplorer`.

### Why this path

The prior Phase B judge panel ranked:

1. **RVH — Reward-Value Hybrid**
2. `OC-WM`
3. `RSSM-Dreamer-Lite`

with the specific required revision:

- **Start with No-T**: drop the learned transition head entirely.
- **Plan only over real graph edges**.
- **Count reward edges first** before assuming the value-learning premise is viable.

This matches the current codebase well because we already have:

- a real observed transition graph in `/Users/ahmed/Documents/ArcAGI3/src/arcagi3/world_model.py`
- a banked submission floor in `/Users/ahmed/Documents/ArcAGI3/src/arcagi3/transfer_explorer.py`
- a proven no-regression discipline around default-off firewalls

### What RVH No-T is

`RVH No-T` keeps exploration and transitions **tabular**. It does **not** try to predict next
states. Instead, it learns a compact **value head** over observed states:

- input = a compact encoding of the observed state key / scene summary
- target = whether this state is on, or near, a known reward-producing path
- use = when the graph is at a branch, prefer real frontier paths that lead toward states with
  high predicted reward potential

The critical constraint is preserved:

- **All execution and reachability stay on real graph edges only.**
- The learned model ranks / prioritizes known frontier choices; it never invents an edge.

That gives us a path to generalization over sparse reward **without** reopening the hallucination
failures of the full world-model planner.

## 3. Goals

### Primary goal

Build a default-off `RVH No-T` explorer that can beat the banked `TransferExplorer` on the real
holdout gate **without** regressing the banked path when disabled.

### Kill-test goal

Before building the online value-guided agent, verify that the graph generated by the banked
explorer actually contains enough reward edges to support learning.

If reward-edge density is too low, the value-learning premise is false and this path should be
killed early.

## 4. Non-goals

- No learned transition model in the first ship (`T(z,a)` is explicitly out of scope).
- No planner over imagined states.
- No changes to submission defaults until the full holdout gate passes.
- No Kaggle submission from this phase until the real local/holdout gate says the branch is
  strictly better than `TransferExplorer`.

## 5. Architecture

### 5.1 Baseline to preserve

`TransferExplorer` remains the production floor.

When the new value layer is disabled, the action trace must remain byte-identical to the current
banked agent for the same seed and environment.

### 5.2 Core components

#### A. Reward-edge probe

A measurement-only harness over the banked explorer that records:

- number of visited states
- number of positive-reward edges
- shortest path length from root to each positive-reward edge
- whether those rewards cluster in a way that can plausibly supervise a value head

This is the first gate.

#### B. State encoder

A compact, CPU-cheap encoding derived from already-observed state structure. First version should
reuse existing object-graph / masked-state information instead of raw pixels.

The point is not rich perception; the point is a stable signal over the **same** state space the
graph already uses.

#### C. Value head

A tiny model that predicts reward-proximity / reward-potential from encoded states.

First version should be intentionally small and train online from replay collected by the banked
explorer:

- positive labels = states on successful reward paths
- hard negatives = visited states not on those paths
- optional soft labels = discounted distance-to-reward on the observed graph

#### D. Value-guided explorer

A wrapper over `TransferExplorer` / the shared graph strategy that changes **ordering only**:

- when several real frontier paths are available, prefer the path whose reachable frontier node
  has higher predicted value
- if the model is cold / uncertain / disabled, fall straight back to baseline ordering

This mirrors the successful factory doctrine used throughout the campaign:

- default-off
- additive
- measurable
- killable without destabilizing the floor

## 6. Data flow

1. Banked explorer runs and builds the observed graph.
2. Reward events identify successful edges and their predecessor states.
3. A replay buffer stores compact state encodings plus labels.
4. The value head trains online or in periodic batches.
5. During exploration, the wrapper scores candidate real frontier nodes.
6. The explorer chooses among **existing** real paths using those scores.

No part of this loop is allowed to generate novel transitions.

## 7. Acceptance gates

### Gate 0 — reward-edge viability

Run the banked explorer on decisive games and count reward edges.

Proceed only if there is enough positive signal to supervise the value head. If there are fewer
than a small handful of positives per game, the AUC-style probe is statistically meaningless and
the design must be reconsidered.

### Gate 1 — offline separability

On frozen replay from the banked explorer, the value head must separate reward-adjacent states
from ordinary states better than chance.

This is still offline: no new agent behavior yet.

### Gate 2 — firewall

With the feature disabled, action traces must remain byte-identical to `TransferExplorer`.

### Gate 3 — local no-regression

The current local floor must remain intact when disabled:

- existing tests green
- submission/default path unchanged

### Gate 4 — real holdout improvement

With the feature enabled, it must produce at least one strict holdout improvement and zero
regressions versus the banked explorer on the real measurement harness.

If not, kill it.

## 8. Risks

### Sparse positives

The main structural risk is that the banked graph may not produce enough reward edges to train a
useful value head. This is why reward-edge counting is the first task.

### Label leakage / wrong target

If we train on frame-change or superficial progress instead of true reward adjacency, we will
repeat Phase A's failure. Labels must come from **real reward structure**, not proxy motion.

### Overstepping the graph

If the learned layer starts inventing edges or overriding the graph's real reachability, the
system regresses back toward the failed planner line. This is forbidden by design.

## 10. Decision rule

If the reward-edge probe or offline separability probe fails, do **not** continue iterating this
architecture by guesswork. Kill it early and return to the next judged Phase B fallback (`OC-WM`).

If the probes pass, implement the smallest default-off value-guided wrapper and measure it on real
holdout immediately.
