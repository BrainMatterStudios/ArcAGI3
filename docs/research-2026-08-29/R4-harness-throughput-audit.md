## 1. Architecture

### 1.1 Notebook → bundle → solver
Cell 1: `RUN_AS_SUBMISSION` from `KAGGLE_IS_COMPETITION_RERUN`. Cell 2: `arc-agi` from the competition wheelhouse. Cell 3: finds the anim bundle via `taaf-kaggle-bundle.json`, verifies the Qwen3.8 mount (16 layer shards / 18 safetensors), writes `taaf_setup_env.json`. Cell 5: regex-rewrites `MODEL_OWNER/MODEL_SLUG/SERVED_MODEL_NAME` inside the bundle's `setup_commands.json` heredoc and runs it — starts vLLM. Cell 6: attestation (fp8/e4m3, transformers 5.8.0.dev0, greedy decode). Cell 8: `ONLY_RESET_LEVELS=true`, `TAAF_MINIMAL_DIAGNOSTICS=1`, unpickles `deploy_target.pkl` + `benchmark_initial.pkl`. Cell 9: 3-game 60-min smoke only when not a scored rerun. Cell 10 (v8 graft): EXPLORER flags, writes 6 files to `/kaggle/working/v8_bundle`, `install()` + hard asserts. Cell 11: waits for `http://gateway:8001/api/games`, `bm.games = _competition_games()`, `n_passes=1`, `await bm.run(soft_end_time=None, minimal_diagnostics=True)`.

`Benchmark.run` (`taaf/benchmark.py:73-249`): deep-copies the solver, calls `start_game()` on all 110 games serially up front (`:149-155`; one shared competition scorecard, `game_api.py:186-195`), then `HarnessSolver.run_games`. `_run_games` (`solver.py:897-927`): `asyncio.Semaphore(28)` + 28-thread pool; each game runs `_HarnessGameSession.play()`. Per-game clock starts when a worker picks the game up (`started_at` `:180`, `runtime_limit_reached :213-218`). A slot is released only on WIN/crash/clock (`should_stop :247-262`) — never on GAME_OVER.

### 1.2 Per-turn loop (`play` `solver.py:264-325`; `ToolAgent.analyze` `tool_agent.py:1706-2063`)
Each analysis step: write `tool_runtime_state.json` (current frame + full frame history) → `analyze()`:
1. Build `[system, *persistent_history, user]`, trim to budget (`:1756-1760`).
2. Loop, unbounded (`LOCAL_ANALYZER_TOOL_STEPS=0` → `None`, `:932, :1783`): trim → POST `/chat/completions` → parse reasoning/content/tool_calls → no tool call ⇒ append "You have not acted yet. Investigate first." and loop (`:1894-1927`); else run `python` in a sandbox subprocess (30 s hard limit `:933`, sandbox `:499-509`); `action([...])` round-trips host↔sandbox over JSON lines (`python_tool_sandbox.py:356-367`) and the host calls `step_env` per action (anim bundle walks batches one at a time); tool result capped at 4,096 chars (`:938-939`).
3. Exit when an action executed (`:1976-1977`), or 60 s after turn start (`LOCAL_ANALYZER_YIELD_SECONDS=60`; checked before each call and after each tool result `:1770-1779, :1784, :1969`), or `should_stop`.
4. On yield the partial turn's messages are kept (`preserve_history` True `:2016-2017`); `play()` re-enters `analyze()` with the same `analysis_step` (`solver.py:321-323`), which appends a fresh user prompt + fresh board image. On any `requests.RequestException` the whole turn is discarded and retried after 1 s (`tool_agent.py:1979-1996`, `solver.py:313-318`).

What the model sees per request (`_build_system_prompt :350-359`, `_build_user_prompt :1161-1256`, `prompts.py`):
- System (~12.7 k chars, constant): game overview + colour legend (`WwgGcBMPRbSYOrNp`), runtime-variable contract, visual guidance, python guidance, tool rules. Anim bundle adds `animation()` paragraphs (`prompts.py:65-71`).
- User: "The code executed N actions… Executed actions: …; still on same level / progressed / game over"; `Current state: step S, level L`; `Valid actions right now: …` (RESET filtered out, `solver.py:117-118` — the model can never reset voluntarily); standing instructions; the carried world model (only lines the model wrote after `World model:` / `Goal model:` / `Action model:` / `Recent findings:` / `Open questions:` / `Plan:` / `Cross-level notes:`, `:263-296, :1128-1145`); a PNG of the 64×64 board at 4× = 256×256 px (`MULTIMODAL_CONTEXT=current_grid`, `MULTIMODAL_UPSCALE=4`; code default 16, `vision_context.py:42-49`). No text grid in the prompt — ASCII board and segmentation are reachable only through `python`, and the prompt forbids printing the whole board.
- Sampling (`openai_compat.py:36-72`): `temperature 0.6, top_p 0.95, top_k 20, chat_template_kwargs {enable_thinking: true}`; no `max_tokens` (`LOCAL_ANALYZER_MAX_OUTPUT=0` → key omitted → vLLM default = up to `max_model_len` − prompt); no seed.
- Thinking across turns: client stores `assistant_message["reasoning"]` (`:1889-1892`); vLLM maps `reasoning` → `reasoning_content` on input (`vllm/entrypoints/chat_utils.py:1535-1539`, local 0.17.2 copy; wheelhouse is 0.19.0); server launched with `--default-chat-template-kwargs '{"preserve_thinking": true}'`; the Qwen3.5-family template re-emits `<think>…</think>` for assistant turns carrying `reasoning_content` (template lines 90-101). Prior thinking IS re-fed inside the window — hence 16–20 k-token requests.
- Truncation (`:1608-1690`): `len(json.dumps(messages+tools))/3` (`:462-467`) vs `32768 − 512 − 512 = 31,744`; oldest messages dropped first, newest kept; the 30-assistant-turn cap (`:151`) never binds because the estimator saturates at ~20–22 k real tokens (14–27 messages measured).
- Level-up: prompt says "You have progressed to a new level!" and world/goal/action/findings/plan notes are erased (only `cross_level_notes` survive, `:1113-1126`). Message history untouched.
- GAME_OVER: runner issues RESET (`solver.py:278-282, :664-666`; 1 action, counted in `actions_per_level`), prompt says "The game is over.", and the same note wipe fires (`:1117`).
- Stagnation: none in the base harness — no stall detector, no forced action; only the anim bundle's exact-board no-op guard (`noop_guard.py`). Loop breakers are the 60-s yield and the per-game clock.
- RESET: only the auto-reset. Gateway swallows RESET when `_action_count == 0` (`reference/arc-agi-toolkit/arc_agi/api.py:318-334`), so post-GAME_OVER resets work.
- Scoring (`taaf/game.py:381-413`): per level `min(115, 100·(baseline/actions)²)` if completed, weight `level+1`, capped at completion share; `actions_per_level` counts every engine action including RESETs.

## 2. Throughput (measured)
Best evidence: `scratchpad/ft09_ablation/ft09-base/` = 28 clones × 7,920 s × conc 28 on the real Kaggle RTX Pro 6000 with the shipped serving stack (Qwen3.6, 08-10); the 3.8 model has the same serving numbers in `_serving_lab3`; no 3.8 full-geometry Kaggle artifact exists.
- Per call: 16–20 k prompt + 1.2 k (3.6) / 2.4 k (3.8) generated. Per-stream 8.6 tok/s at 28 → a 2.4 k completion alone is ~280 s; lab p50 128 s / mean 161 s per 1.6 k-token request at conc 28.
- Per turn: 156 s mean / 118 s median; 1.2 requests; ~2 actions. ⇒ ~50 turns and ~88 actions per game per 7,920 s (median 85; 3.8 on Modal 45–126).
- GPU: util 100 %, KV 81–96 % full, aggregate decode only 235–300 tok/s because at 28 streams decode is KV-bound and 12–13 prefill tokens are recomputed per generated token (prefix hit 2–18 %): context is always at budget and `_trim_messages_for_context` drops the oldest messages every turn, so the prefix changes on nearly every call. Prefill ~3,000 tok/s mean.
- Ramp: 500–550 gen tok/s at 27–28 running in the first 2 min (short contexts) → 150–280 once contexts hit 16–20 k. Context length, not batch size, throttles the GPU.
- Tokens per game: ~64 k generated + ~1.0–1.1 M prompt per 7,920 s.
- Time split inside a game: 26 % of wall in slices ending with no action; ~5–10 % engine/tool (per-action gaps ≤ 1 s); rest LLM decode/queue. Setup 10 min; teardown 5 s.

## 3. Budget math
- 110/28 = 3.93 waves; wave 1 starts ~630 s; wave 4 (26 games) ~24,400 → ~32,300 s. Yes: the 9 h is 4 × 2.2 h of play + 10 min setup with ~90 s spare. Two slots idle all of wave 4 (4.4 slot-hours, 5 % of capacity). No game ends early (0 wins), so nothing is reclaimed. `soft_end_time` is None at eval, so if setup slips > 90 s the kernel is killed mid-wave-4 (partial play is already on the gateway scorecard, but the scorecard close in `game_api.py:78-86` would never run — untested).
- GPU: saturated but inefficient — most token work is re-prefill; useful decode 235–300 tok/s ≈ 8.6–10.6 tok/s per game.
- vLLM startup 570–610 s to ready (pip 139 s, weights 85–202 s, graph capture/warmup the rest).
- Marginal cost of one more action ≈ 0.6 requests ≈ 60–105 s of a game's clock (91 s median).
- Halve thinking: decode share drops ~40 %, prefill (16–20 k) unchanged ⇒ turn 156 → ~110 s ⇒ ~1.4× actions/game. Quality effect contested (token-diet memory).
- Double concurrency (56, 2 waves × 15,840 s): KV already 81–96 % full at 28 (vLLM: ~10 full-length requests fit) ⇒ preemption/recompute; per-stream rate ≈ halves while each game gets 2× wall ⇒ actions/game ≈ unchanged; the 2 idle slots vanish (+5 %). Halving context per request is worth more than any concurrency change: doubles resident capacity and prefix locality and lifts per-stream decode (lab: 8 streams → 27 tok/s each).

## 4. Binding constraint
From 83 full-length plays (transcript profile) and the 28-clone rows:
1. Model comprehension (wrong/aimless actions) is the primary limiter for the 45–55 % of games ending at 0 levels. They are not action-starved: 08-11 shipped wave zero-level games spent 91–1,304 actions on L1 vs baselines 22–78 (ar25 291 vs 32, cn04 174 vs 29, dc22 234 vs 59, sk48 1,304 vs 61, ls20 379 vs 22). sk48/k017 fired 20–140-action movement batches for 2.2 h, hit GAME_OVER 7×, never formed a goal model. Human-efficiency arithmetic: 200 actions → 3.5 levels; the agent reaches 1.0–1.4.
2. Harness loop waste is second and mechanical: the 60-s yield is shorter than one call (118 s median at conc 28), so nearly every slice is one call; an investigation-only call ⇒ yield ⇒ new prompt + image ⇒ re-grounding. 26 % of play wall in action-less slices; stuck steps of 17–59 slices (bp35 step 7: 73 min, 20 slices, 1 action; ar25 step 13: > 65 min). Each slice grows context → more trimming → more prefill → slower calls: a feedback loop.
3. Context/forgetting is real but secondary: working window 4–9 assistant turns (~2–4 actions) because 16–20 k tokens re-feed prior reasoning and tool dumps; long-term memory is only the self-written notes, wiped on every GAME_OVER and level-up. Identical python snippets re-issued within turns (doc count 71; consistent with the slice counts).
4. Wall clock caps depth for games the model does understand: ~88 actions/game buys ≤ 1.9 levels at human efficiency (3.5 at 200), and the model spends 1.2–2.5× human on levels it clears (cd82: 135 actions for a 55-baseline L1). Level 4+ (needed for > 60 % of max score) needs 400+ actions/game — 4–5× today's throughput — even with perfect comprehension. Today's model is comprehension-bound first, loop-waste-bound second; a much better model would be throughput-bound at this geometry.
5. Not binding: engine/gateway (per-action gaps ≤ 1 s), 30-s tool timeout (12–13 per ~1,500 turns), tool errors (69 tracebacks per ~5,000 acting slices), request timeouts on Kaggle (max turn 901 s ≈ one 900-s timeout).

## 6. Cheapest changes most likely to raise levels completed (ranked)
1. Stop the 60-s yield from fragmenting turns (`LOCAL_ANALYZER_YIELD_SECONDS` 60 → ≥ 900 or 0, set in `os.environ` after cell 5, before `bm.run`; optionally `LOCAL_ANALYZER_TOOL_STEPS=6` as the loop bound). Evidence: yield < call latency (118 s median) ⇒ one call per slice; 26 % of wall in action-less slices; 17–59 slices per stuck step; every slice appends prompt + image and forces trimming. `should_stop` is still checked before every call (`tool_agent.py:1770-1786`), so the deadline is unaffected. Testable offline via the smoke hook.
2. Make the prompt prefix cache-stable (`_trim_messages_for_context`, `tool_agent.py:1672-1690`): trim with hysteresis (drop to ~60 % of budget in one go) so the prefix survives many turns; keep image/step summary at the end. Evidence: prefix hit 2–18 %, 12–13 prefill tokens per generated token, 500 → 235 tok/s collapse as contexts filled. Expected 1.3–1.6× more turns per game. ~30 lines; testable in a `_serving_lab`-style kernel.
3. Shrink the request (`LOCAL_ANALYZER_CONTEXT_WINDOW` 32768 → 16384, or drop `assistant_message["reasoning"]` for turns older than the last). Evidence: real memory is already 4–9 turns; 16–20 k tokens/request is what makes decode 8.6 tok/s/stream and KV 81–96 % full; lab: 8 resident streams decode 3× faster each. Env-var only.
4. Do not wipe the world model on GAME_OVER (`tool_agent.py:1113-1126`; keep the level-up wipe). Evidence: GAME_OVER is recoverable and frequent (7× in one sk48 play; 39 in 28 transcripts); the notes are the only cross-turn memory. One line.
5. Bound batched action spam (cap `action([...])` at ≤ 10 per call in `_normalize_python_actions`, `tool_agent.py:1378-1414`). Evidence: 20–140-action blind batches (sk48 1,304 actions on L1 vs baseline 61) burn efficiency and trigger GAME_OVERs; also removes > 30-s tool timeouts on long batches. Risk: slows legitimate path plans (median batch ~2).
6. Reclaim idle wave-4 capacity / remove the 90-s cliff: set `bm.solver.max_runtime_s_per_game` from measured setup time (e.g. `(32400 − setup − 300)/4`) in cell 11, or run 37 concurrent × 3 waves only after change 3 has freed KV. Evidence: 4 × 7,920 + 630 = 32,310 of 32,400 s; 2 slots idle in wave 4. ~5 % capacity plus removal of a hard-kill risk.
7. Cap the output tail (`LOCAL_ANALYZER_MAX_OUTPUT` ≈ 4096): p90 request 3.4 k generated; forensics report thinking-only dead completions; a cap bounds the tail without touching the median (2.2 k). Quality effect contested — run behind the smoke hook first.

Not recommended from this evidence: raising concurrency (KV-bound), cutting thinking below the median (comprehension is first-order), more grind/specialist grafts (inert on 109/110 games).
