3 · The two real levers

Lever A — Single-play efficiency buildable now

The documented 0.33 → 0.68 path. Minimize actions on the levels we already solve, in a single play with no resets. The campaign concluded "efficiency is eval-inert" — but that verdict came from geodesic reset-then-replay, the exact pattern that zeroes the squared metric. The correct lever is lean first-solve, which we never measured cleanly.

Reverses a campaign error. Evidence: thylinao1 DECISION-LOG + the RHAE action-ratio math. Needs a 1-day local audit to confirm our agent is bleeding score to resets/over-exploration.

Lever B — First-reward manufacture gated on a 1-day test

The 0.33 → ~0.45 path. A small, frozen, offline-authored library of executable goal-archetypes (target-click, reach-unique-cell, collect-all, toggle-all…) run as strictly-additive max-over-plays pursuit, gated to fire only when coverage stalls with zero reward. It enumerates-and-pursues a designer-intent goal instead of inferring it — crossing the first reward on archetype-shaped zero-games where pure coverage walls.

sb26 L0 (cracked in 9 actions) is the existence proof that a zero-game can go 0→positive this way.

5 · Honest ceiling — and the Tufa question

No buildable offline paradigm in the panel reaches Tufa's 1.17%. CGPP's realistic landing is ~0.40–0.48 with a hard 0.33 floor (additive, can't regress). It converts 1–2 archetype-shaped hidden zero-games and harvests deep-level efficiency; it does not crack genuinely-novel-mechanic games (invisible gating like ls20 rotation, undecodable wins like g50t, combinatorial no-feedback binding like sb26 L1). W1 is real and re-emerges one level down.

To actually outperform Tufa (your stated goal) the two stackable levers are: (A) super-human action-efficiency via compiled optimal solvers on mechanics once ID'd — this is what pushes the very top past 1.0 on the squared metric — and (B) first-reward manufacture to unlock more scored levels. Tufa's own edge is an undisclosed "novel approach"; their published 58%-RHAE method is online GPT-5.5 — illegal offline. There is no shortcut to copy. The credible path is: close the efficiency gap first (buildable, reverses a campaign error), add first-reward manufacture (gated), and treat beating-Tufa as the research frontier it genuinely is.

6 · Two decisive <1-day experiments (run before any build spend)

Exp 1 — Efficiency audit Lever A

On 3–4 public levels we already solve, measure our agent's actual action count and the resulting per-level RHAE, and check how much is lost to resets / over-exploration vs a lean single-play solve. We hold the engine + environment_files/.

If we're at ~17× human and resets dominate → a lean first-solve rewrite is a real, immediate 0.33→0.5+ lever. If already lean → efficiency is tapped and Lever B is the only path.

Exp 2 — Held-out predicate-recall Lever B gate

Hand-extract the true win-condition of all 8 public zero-games from environment_files/*/*.py (we hold the source). Build a compact ~8–12 predicate library leave-one-out. Measure: does the frozen top-K (K≤4) contain the TRUE win-condition of ≥5/8 held-out games?

≥5/8 → designer-intent vocabulary is compact & transferable → build CGPP. <5/8, each bespoke → win-conditions don't share a vocabulary → ship only the sb26-L0 integration, don't build the library.

7 · Recommended plan

  1. Run Exp 1 + Exp 2 (1–2 days, local, free). They resolve the campaign's central tension on ground truth we already possess, before any frontier-authoring spend.
  2. If Exp 1 shows efficiency headroom: build the lean single-play solver (no reset-replay) — the documented 0.33→0.68 path. Highest-confidence, evidence-backed, reverses the "efficiency inert" error.
  3. If Exp 2 passes (≥5/8): build CGPP — start with 3 archetypes only, strictly-additive max-over-plays, stall-gated, anchored behind transfer_s0.
  4. No-regression firewall (non-negotiable): archetype/efficiency plays are additive and gated to never activate on a game coverage already wins → banked 0.33 floor by construction. The moment anything touches coverage ordering, it becomes the killed GraphRanker. And re-push the kernel before submit (the geodesic no-op lesson).
