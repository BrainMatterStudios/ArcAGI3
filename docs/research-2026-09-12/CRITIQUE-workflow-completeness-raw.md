Close: `docs/RESEARCH-2026-08-21-bug-lever-hunt.md` (the MTP+prefix section) before touching `modal_flashnext_serve.py`.

2. **Step 4's "no RESET" restart graft does not exist as code, and its premise collides with a verified fact.** `submission/_throughput_v1/graft_retry.py:411,454` — `fire()` always issues `GameAction.RESET` through the action path; `RETRY_CLEAR_HISTORY` (`:158`) is a dose on top of that RESET, not a substitute. So the $2.5 kill test needs an uncosted code change first. Second, verifier 2 measured 461 zero-history calls (n_messages=2) acting 0.0% of the time — a full wipe manufactures exactly that call shape, so the kill test must gate on the *first post-wipe call's* acting rate, not only "actions/call < 2.0" over the run. Third, RESET (+1) and re-exploration actions accumulate into the level's action count (memory `arcagi3-action-accounting-measured.md`), and the efficiency term is quadratic (`arcagi3-scoring-is-convex-in-depth.md`); the kill test reads levels, never `results.json` score. Close: add a no-RESET branch to `fire()`, and read per-game `score` alongside levels.
