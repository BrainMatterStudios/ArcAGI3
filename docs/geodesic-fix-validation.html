What this does to the score

Verified scoring (installed arc_agi/scorecard.py:123): level_score = min(baseline÷actions × 100, 100), averaged over all game levels (unreached = 0), per-game = max over plays.

The geodesic action counts (mostly 13–105) are now in the human-plausible range, so reached levels jump toward the cap; transfer’s thousands score near zero. Example (tu93 L1, assuming a human baseline ~30):

actionslevel score
transfer431~7 / 100

So reached levels go from single-digit to near-cap — a 10–100× per-level score increase on the 15 helped games, strictly additive (max-over-plays never takes a worse play).

Honest uncertainty

  • Human baselines are unknown offline. The exact per-level score needs the hidden games’ baseline action counts. If humans are very efficient (small baseline), scores land below the cap but still far above transfer. The direction and magnitude (large) are robust; the precise number is not.
  • Coverage still bounds per-game score. Efficiency maximizes the score of reached levels; it does not reach more levels. Games where we only reach L1 of many are still capped by that.
  • The 8 W1 zero-games are untouched. Efficiency can’t help where we never reach L1 — that gap needs genuine mechanic-solving (the June-30 adopt-and-harden target).
  • Deploy requires re-pushing the kernel. Kaggle v22 was built with the bugged no-op; the fix must be re-pushed before submission or it ships transfer-only (~0.33).
