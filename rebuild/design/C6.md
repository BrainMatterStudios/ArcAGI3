# C6 — Planner

**Confidence:** 0.72

## Summary
Synthesis of the three proposals into one blueprint. All three converge on the same load-bearing safety architecture (new pure module `planner.py`; a new "plan" phase inserted between `navigate` and the `graph` fallback in `HybridPolicy._choose`; flag default-off; decline-to-None on any uncertainty; execution-time divergence-abort mirroring `GraphStrategy._expect`). I take Proposal 1's coordinate discipline and direct reuse of the tested `OccupancyMap.astar` (it keeps everything in (row,col) centroids and passes them straight to `astar`, eliminating an entire class of lattice<->centroid conversion bugs that Proposals 2/3 reintroduce); Proposal 3's conservative simulate() with mandatory, isolation-tested sokoban corner-deadlock pruning and unknown-affordance->BLOCK default; Proposal 3's open-ALL-doors-on-any-toggle rule (which exactly matches switchdoor.py semantics — verified) plus replay-validated subgoal decomposition for key->door; and Proposal 2's affordance-filtered symbolic state (only interactive objects enter the planning state, keeping branching tractable on unseen games) and greedy-nearest collect tour. I discard Proposal 2's monolithic generic best-first-over-SymState catch-all as the default (too much surface, weak no-regression story) and Proposal 1's `OccupancyMap.with_unblocked` edit to spatial.py in favor of door-unblocking handled entirely inside the planner's simulate so spatial.py stays byte-for-byte unchanged. Reach reuses astar verbatim; push uses a dedicated per-block joint A* in lattice space; toggle uses reach->reach replay decomposition.

## Algorithm
COORDINATE CONVENTION (pin first; verified against code): perception centroids and mm.avatar_centroid are (row,col) floats; OccupancyMap.astar(start,goal) takes (row,col) FLOAT centroids and quantizes internally; engine clicks are (x=col,y=row). Planner internal math is (row,col); blocks/markers stored as quantized lattice cells via occ.quantize ONLY for the push joint-search; reach/collect feed centroids straight to astar. Single click-conversion point at emit.

TOP-LEVEL plan(grid, mm, occ, aff, goal) -> Plan|None:
  if goal is None or goal.confidence < CONF_MIN: return None        # gate 1
  if mm is None or not mm.ok: return None                           # gate 2 (no avatar)
  ac = mm.avatar_centroid(grid); if ac is None: return None
  if not occ.usable: return None  # gate 3: needs 2D axis-aligned moves (spatial.usable)
  dispatch on goal.kind:
    REACH        -> _plan_reach
    COLLECT_ALL  -> _plan_collect_all
    PUSH_TO      -> _plan_push
    TOGGLE/key   -> _plan_toggle_then_reach
    else         -> None  (NO generic catch-all -> falls to graph; the no-regression floor)

_plan_reach: targets = centroids of objects with aff.kind==GOAL/target_color, sorted by
  Manhattan to ac; for t in targets: ids = occ.astar(ac, t); if ids: return Plan([("S",a) for a in ids]). else None.
  (astar used VERBATIM — zero new pathfinding code.)

_plan_collect_all: greedy nearest tour. cur=ac; remaining=collectible centroids;
  while remaining: nxt=nearest(cur); leg=occ.astar(cur,nxt); if leg is None: return None;
  append; cur=nxt. Return concatenated, BUT policy re-plans after each collection (objects
  vanish), so a stale tour self-heals.

_plan_push (sokoban, per-block joint A*, lattice space):
  block = quantize(nearest pushable centroid); target = quantize(marker centroid)
  state=(avatar_q, block_q); goal: block_q==target. cost=#actions; h=Manhattan(block,target).
  expand via simulate_push((a_q,b_q),aid,unit,occ): 
    nxt=a+unit; if nxt in occ.blocked: avatar stays (no-op, won't be chosen);
    if nxt==b: beyond=b+unit; if beyond in occ.blocked OR beyond is a CONFIRMED non-target
       corner (two perpendicular occ.blocked neighbors): return None (illegal/deadlock push);
       else move both; else avatar->nxt.
  Cap PUSH_BUDGET expansions; on overflow return None -> graph fallback (today's push path).

_plan_toggle_then_reach (key->door; matches switchdoor: ANY switch opens ALL doors):
  sim=current occupancy snapshot; acts=[]; for tog in toggles ordered greedily:
    leg=astar to tog over CURRENT walls (doors still closed); if None return None;
    acts+=leg; replay: mark ALL door cells passable in sim (conservative, matches engine).
  goal_leg = astar to goal cell over sim WITH doors open; if None return None;
  return Plan(acts+goal_leg). If model wrong, runtime divergence-abort drops to graph (which
  already solves switchdoor).

EXECUTION (in policy): buffer self._plan; each tick pop front; BEFORE popping, _plan_diverged:
  recompute avatar centroid; if not within 0.5 lattice-step of simulate's prediction for the
  last executed action -> drop plan (self._plan=[]) -> graph fallback. Re-plan only when buffer empty.

OCCUPANCY LEARNING (free, no extra actions): in decide(), when prev action was ("S",id) and
  occ exists, call occ.observe_move(prev_centroid, id, cur_centroid) — same data already collected.

GROUNDING build_plan_state: objs=connected_components(grid,bg); skip mm.avatar_colors and
  distractor_colors; for each color aff.kind(color,conf); conf<AFF_CONF_MIN -> treat as BLOCK
  (conservative). If goal references a color with zero grounded objects -> return None.

## No-regression strategy
Five layered guards, every one verified against real code:
1) FLAG DEFAULT-OFF: enable_planner=False ships first. With flag off, _choose is byte-for-byte identical (the inserted block is fully guarded by `if self.enable_planner`). Existing test_reactive_solves_all_local_games (8/8) and push 3/3 run with flag off -> provably unchanged. Flip default only after the measurement gate.
2) ADDITIVE EARLY-RETURN ONLY: the plan block returns early ONLY when it has a validated plan action; EVERY decline path (None goal, conf<CONF_MIN, !occ.usable, astar None, push budget exceeded, grounding self-check fail, plan diverged) falls through to the EXACT graph/navigate code that produces today's results. The planner can only add solved cases.
3) NO generic catch-all search as default: unknown goal kinds -> None -> graph. This is the deliberate floor; Proposal 2's monolithic SymState search is rejected as default because it widens the surface that could mis-plan and starve the budget.
4) RUNTIME DIVERGENCE-ABORT (reuses the proven GraphStrategy._expect pattern): _plan_diverged drops any plan the moment the real avatar centroid disagrees with simulate's prediction, so a wrong forward model / wrong affordance / wrong door-linkage costs <=1 wasted action then reverts to graph — which already solves push (joint-graph) and switchdoor (causal explorer).
5) MANDATORY sokoban deadlock pruning, isolation-tested: simulate_push returns None for any push into a CONFIRMED corner; unit tests assert None on every corner-push of a 3x3 fixture BEFORE any integration. This is the specific guard for the component this codebase has repeatedly regressed.
6) spatial.py UNCHANGED: astar/observe_move/quantize/usable not edited at all, so test_spatial.py stays green by construction.
7) ONE-SHOT planning per level + PUSH_BUDGET cap: bounds CPU so actions/sec (== levels) never regresses.

## Risks
1) Coordinate (x,y)/(row,col) confusion — THE most likely bug (verified astar takes (row,col) centroids). Mitigation: keep reach/collect entirely in (row,col) centroids fed straight to astar (Proposal 1 discipline); quantize only inside push; single click conversion x=col,y=row at emit; unit test asserts a known open-board reach equals the same action list as test_spatial test_astar_straight_line.
2) Wrong affordance/goal before C3/C5 land — Mitigation: unknown->BLOCK (conservative), derive_minimal reproduces today's navigate-to-nearest so the floor == today; divergence-abort + decline.
3) Sokoban corner-deadlock (the historically-regressed case) — Mitigation: mandatory pruning + isolation tests + graph fallback still solves push regardless; only prune on CONFIRMED occ.blocked neighbors so unknown space is never falsely declared deadlock.
4) Door-toggle linkage wrong — verified switchdoor opens ALL doors on ANY switch, so open-all model is exact for the dev game; for unseen variants, replay-validation + divergence-abort + graph fallback (already solves switchdoor) cover it.
5) Push budget blowup on large boards — capped expansions -> None -> graph. 
6) Click-only games (no avatar) — mm.ok / occ.usable gates make the plan phase a no-op; click salience path untouched.
7) Occupancy staleness across levels — recreate occ in _new_level (walls differ per level), mirroring mm reset.
8) astar's `bound` (4*Manhattan) may reject long detours — acceptable: returns None -> graph; do NOT touch astar.
Residual lower-confidence area: collect-tour optimality and multi-block sokoban interactions (per-block plans can conflict) — caught at execution by divergence-abort, reverting to graph rather than attempting fragile joint search.
