# C4 — Forward world model

**Confidence:** 0.83

## Summary
Synthesized blueprint for a training-free, object-level forward world model in a NEW file src/arcagi3/forward_model.py, consumed ONLY by C6/C7 (never imported by policy.py/agent.py in this component). It lifts a frame into a hashable object-level Scene via the existing P.connected_components + MotionModel.avatar_colors, then ForwardModel.predict(scene, action)->Prediction applies a faithful generalization of push.py sokoban semantics plus C3 affordances, returning the next Scene with typed effects, a confidence, and — critically — a `known` flag. The design's spine is Proposal 3's verified insight: push today is solved by GraphStrategy BFS over the joint object_state_key, NOT by a planner, so C4 must be a pure side-effect-free predictor whose worst-case failure is "decline → fall through to today's exact code path." Three regression firewalls (all adopted): (1) zero live-path edits, proven by grep; (2) refuse-on-uncertainty + a `known=False` edge that the planner is contractually forbidden to traverse without real verification (Proposals 2+3); (3) a `scene_key()` that is byte-identical to P.object_state_key (Proposal 1's linchpin), so predicted keys unify with the WorldModel graph and predict-then-verify is exact. The single most important generality choice (Proposal 2): C4 never asserts an effect it has not observed — unknown colors yield refuse/`known=False`, turning ignorance into directed exploration rather than a hallucinated success that would burn the budget.

## Data structures
Scene is object-level and hashable (frozen Entity with frozenset cells; tuple of entities), NOT a 64x64 grid — rollouts are O(#objects) per step (~tens) not O(4096). Crucially NO stable cross-frame eid is stored (Proposal 3's insight): within-step identity is the _occ index; cross-step verification is by Scene.key()==object_state_key (bbox+size), so object-id churn between frames is harmless and C4 has no hard dependency on C1. _occ: dict[(r,c)->entity_index] built once per Scene for O(1) occupancy. Prediction carries both `valid` (model refuses) and `known` (relied on an unknown affordance) plus `confidence` — the planner needs all three to decide trust vs verify-in-reality. Affordance access is via a Protocol with a StubAffordanceModel so C4 compiles/tests fully before C3 lands.

## Algorithm
SCORING OF THE THREE PROPOSALS (each /5):

P1 (reuse-heavy, scene_key==object_state_key linchpin):
- correctness 4: solid step/try_push; but its NONE/absent-affordance fallback says "treat as BLOCK if occupancy says blocked" which on contact defaults toward BLOCK — risks contradicting spatial.py's optimistic free-space default and mispredicting.
- generality 3.5: TOGGLE non-mutating (good, honest); but no first-class `known=False` exploration-driver; degradation = "motion model the agent trusts" is fine but less self-falsifying.
- no-regression 4.5: default-off kwarg + measurement-only validation hook is excellent; the one weakness is it DOES edit policy.py (inert kwarg + guarded construct + validation counter), a larger surface than strictly needed.
- feasibility 5: pure CPU, reuses memoized CC. Best single idea: extract _object_tuples so scene_key == object_state_key exactly.

P2 (honesty-first, `known` flag, verify_step shadow auto-disable):
- correctness 4.5: occupancy-first then affordance ordering is the right precedence (empirical ground truth outranks color guess); push single-step + behind-free check correct.
- generality 5: best. `known=False` for unknown objects → planner routes to physically touch them → that's how C3 learns. NONE is first-class. CNN drop-in behind same Prediction interface.
- no-regression 5: strongest. ZERO imports in policy.py/agent.py (grep-proven); verify_step shadow mode that AUTO-DISABLES planning per-game on confident-but-wrong → structurally self-falsifying. This is the decisive anti-regression mechanism.
- feasibility 4.5: frozenset cells + bbox key; tiny perf concern with frozenset(cells) hashing at scale, mitigated by bbox-summary key.
- weakness: uses tracker/oid (C1) in scene_from_grid; its key() is repr-based but NOT proven byte-equal to object_state_key (P1 is better here).

P3 (push-fidelity-first, verified root-cause):
- correctness 5: ONLY proposal that correctly diagnosed how push actually works (graph BFS over joint key) and line-aligns predict_move to push.py (OOB→no-move, push-into-wall→no-move, block-on-target→reward). TDD push-fidelity test vs real Push env across 4 dirs × 3 levels is the gold standard.
- generality 4: good refuse defaults; eids within-step only (correct — cross-step verification is by object_state_key not eid, so churn is harmless — a sharp insight P1/P2 underweight).
- no-regression 5: best-articulated five-layer defense; correctly identifies "graph fallback must never be bypassed" and "C4 only narrows navigate phase later."
- feasibility 5.
- weakness: NONE_DEFAULT_BLOCK ambiguity in pseudocode (resolved later to refuse, but messy); no scene_key==object_state_key guarantee spelled out as code-sharing.

VERDICT: P3 has the best correctness + root-cause grounding; P2 has the best generality + the killer self-falsifying verify_step auto-disable; P1 has the best scene_key linchpin. Synthesize all three.

DATA STRUCTURES (forward_model.py):

  Affordance enum: BLOCK, PASS, PUSH, COLLECT, TOGGLE, GOAL, HARM, NONE
  class AffordanceModel(Protocol):
      def get(self, color:int) -> tuple[Affordance, float]   # (kind, confidence), default (NONE, 0.0)
      def links(self, color:int) -> list[int]                # TOGGLE targets; [] if unknown
  StubAffordanceModel: dict-backed, default (NONE,0.0) — lets C4 be built/tested before C3.

  @frozen Entity: color:int, cells:frozenset[(r,c)], is_avatar:bool   # NO eid (within-step identity via cells/bbox; cross-step via scene_key)
  @frozen Scene:
      bg:int, shape:(H,W), entities:tuple[Entity,...]
      avatar_cells: frozenset (union of is_avatar entity cells)
      _occ: dict (r,c)->entity index   # built once in from_grid
      terminal:bool=False, reward:float=0.0
      def key(self)->bytes  # == P.object_state_key on the equivalent grid (SEE LINCHPIN)
  @frozen Prediction:
      scene:Scene, moved:bool, reward_pred:float, events:tuple[str,...],
      valid:bool,        # False => model refuses (low conf / unknown delta / unmodelled click)
      known:bool,        # False => relied on a NONE/unknown affordance; planner must verify in reality
      confidence:float   # min over affordances relied on (1.0 for pure motion/bounds)

LINCHPIN (from P1): scene_key MUST equal P.object_state_key.

  from object_state_key (keep object_state_key behavior byte-identical; test_perception stays green).
  Scene.key() = repr(_object_tuples_from_entities(self)).encode(). Dedicated test asserts equality
  on real game grids. This makes predict-then-verify EXACT (predicted key == real next key when correct).

from_grid(grid, bg, motion, affords) -> Scene:
  objs = P.connected_components(grid, background=bg)        # memoized, existing
  avatar_colors = motion.avatar_colors                      # existing multi-color set
  drop nothing by default; mark is_avatar = color in avatar_colors
  (ignore_colors = policy distractor_colors passed in → excluded from entities so animations
   never trigger spurious BLOCK/events — from P1's risk table)

predict(scene, action) dispatch:
  if action[0]=="C": return predict_click(...)
  if action==("S",7): return _refuse(scene)        # undo not invertible in sim
  return predict_move(...)

predict_move(scene, aid):   # FAITHFUL GENERALIZATION OF push.py (P3) + occupancy-first (P2)
  if aid not in motion.deltas: return _refuse(scene)        # no learned effect
  (dr,dc)=motion.deltas[aid]
  if (dr,dc)==(0,0): return Prediction(scene, moved=False, events=("noop",), valid=True, known=True, conf=1.0)
  if not motion-axis-usable for this delta? still proceed cell-wise (predict doesn't need lattice)
  avatar=scene.avatar_cells; dest={(r+dr,c+dc) for (r,c) in avatar}
  # 1. OOB for ANY avatar cell -> blocked, no move (== push.py:62, ALWAYS known/valid)
  if any cell OOB in dest: return Prediction(scene, moved=False, events=("blocked:oob",), valid=True, known=True, conf=1.0)
  # 2. classify each destination occupant
  pushset, contacts, conf, known = set(), set(), 1.0, True
  for cell in dest:
      occ = scene._occ.get(cell)
      if occ is None or scene.entities[occ].is_avatar: continue
      kind,c = affords.get(scene.entities[occ].color); conf=min(conf,c); contacts.add(occ)
      if c < min_confidence:                              # P3+P2 refuse-on-uncertainty
          return _refuse(scene)                            # NOT block, NOT pass: decline
      if kind==NONE: known=False; return Prediction(scene, moved=False, events=("unknown",), valid=True, known=False, conf=conf)
      if kind in (BLOCK,): return Prediction(scene, moved=False, events=(f"blocked:{occ}",), valid=True, known=True, conf=conf)
      if kind==HARM: return Prediction(replace(scene, terminal=True), moved=False, events=(f"harm:{occ}",), valid=True, known=True, reward_pred=-1, conf=conf)
      if kind==PUSH: pushset.add(occ)
      # PASS/COLLECT/GOAL/TOGGLE: avatar enters; handled below
  # 3. resolve pushes (single-block, == push.py:65-71)
  new_entities=list(scene.entities)
  for occ in pushset:
      shifted={(r+dr,c+dc) for (r,c) in scene.entities[occ].cells}
      if any OOB in shifted: return Prediction(scene, moved=False, events=("blocked:push_oob",), valid=True, known=True, conf=conf)
      blockers = {scene._occ.get(s) for s in shifted} - {None,occ} - avatar_indices
      if blockers: return Prediction(scene, moved=False, events=("blocked:push_into",), valid=True, known=True, conf=conf)
      # chain push (box into box) NOT supported -> if a blocker existed we already declined above
      new_entities[occ] = replace(entity, cells=frozenset(shifted))
  # 4. move avatar; apply COLLECT/GOAL/TOGGLE; compute reward
  move all is_avatar entities by (dr,dc); events=[]; reward=0.0
  for occ in contacts:
      kind,_=affords.get(color)
      if kind==COLLECT: drop occ; events.append(f"collect:{occ}")
      if kind==GOAL: reward=1.0; events.append(f"goal:{occ}")
      if kind==TOGGLE: events.append(f"toggle:{occ}")    # do NOT mutate paired obj in v1 (P1: honest, low-conf); links() reserved for C2/C5
  # push-onto-goal win (== push.py:76): if a pushed box now covers a GOAL-affordance cell -> reward=1.0, events+=("push_goal",)
  for occ in pushset: if shifted overlaps a GOAL entity cell: reward=1.0; events.append("push_goal")
  return Prediction(new_scene(new_entities, reward), moved=True, reward_pred=reward, events=tuple(events), valid=True, known=known, conf=conf)

predict_click(scene, ("C",x,y)):   # P2+P3: decline unless C3 learned a click effect
  occ = scene._occ.get((y,x))       # x=col,y=row (matches to_game_action)
  if occ is None: return _refuse(scene)
  kind,c = affords.get(color)
  if kind in (TOGGLE,COLLECT,GOAL) and c>=min_confidence: model removal/marking like move case
  else: return _refuse(scene)        # keeps click games on existing salience+graph path

_refuse(scene): Prediction(scene, moved=False, reward_pred=0, events=("refuse",), valid=False, known=False, confidence=0.0)

rollout(scene, actions, max_steps=64, stop_on_reward=True):  # P2+P3
  out=[]; cur=scene
  for a in actions[:max_steps]:
      p=predict(cur,a); out.append(p)
      if not p.valid or not p.known or p.scene.terminal: break   # halt at first uncertain edge
      cur=p.scene
      if stop_on_reward and p.reward_pred>0: break
  return cur, out

verify_step(scene, action, actual_next_grid) -> bool:   # P2 (the decisive safety net for C7)
  p=predict(scene,action)
  if not p.valid or not p.known: return True   # we made no confident claim
  return p.scene.key() == P.object_state_key(actual_next_grid, bg, ignore)
  # C7 runs this in shadow on every real action; if confident predictions mismatch above a
  # threshold for a game, C7 DISABLES planning for that game and reverts to HybridPolicy.

## No-regression strategy
FIVE-LAYER DEFENSE (all verified against the codebase):

1. NOT IN THE LIVE PATH (decisive). C4 is a new module with no import added to policy.py/agent.py/world_model.py. The 8/8 local suite (27/27), push 3/3, and pytest run the UNCHANGED HybridPolicy. The ONLY edit to existing source is a behavior-preserving refactor of object_state_key into _object_tuples (test_perception.py locks it byte-identical). Acceptance gate: `grep -rn forward_model src/arcagi3/policy.py src/arcagi3/agent.py` returns empty.

2. PUSH IS SOLVED BY THE GRAPH FALLBACK, NOT C4 (root-cause from Proposal 3, verified). push.py + policy.py confirm: navigate walks avatar to block centroid, stalls (nav_stale>=2 once blocked), falls through to GraphStrategy.decide which BFS-searches the joint object_state_key (avatar 14 + block 6 + target 4 all encoded with bbox+size). C4 never touches this path in this component; C7 only narrows the NAVIGATE branch and always falls through to the untouched graph fallback when C6 declines.

3. REFUSE-ON-UNCERTAINTY + known=False CONTRACT. predict() returns valid=False when any relied-on affordance conf < min_confidence (0.6), delta is unknown, or click is unmodelled — NOT "assume passable" (would desync through real walls) and NOT "assume block" (would contradict spatial.py's optimistic free-space default at spatial.py:7-8). For a known-but-NONE color it returns known=False. rollout halts at the first invalid/unknown edge. C6 is contractually forbidden (asserted in C6 tests) from committing to a plan crossing an unknown edge without real verification. A pessimistic C4 can only fail to help, never misdirect.

4. EXACT scene_key + PREDICT-THEN-VERIFY. Scene.key()==P.object_state_key means a correct prediction's key equals the real next key exactly. C6 executes plans one real action at a time and aborts on first key mismatch (mirrors the existing plan-divergence abort GraphStrategy.decide line 92-95), converting any prediction error into "wasted <=1 action + safe fallback." verify_step() lets C7 shadow-check every real action and AUTO-DISABLE planning per-game on confident-but-wrong (self-falsifying — the model removes itself the moment it is wrong on a game).

5. PUSH-FIDELITY FROZEN BY TEST (Proposal 3, TDD). Dedicated test drives the real Push env (as test_agent.py does), builds a Scene each step with PUSH affordance for color 6 + GOAL for color 4, and asserts predict(scene,("S",aid)).scene.key() == object_state_key(real_next_frame) for all 4 directions × 3 levels. Push semantics are line-aligned to push.py (OOB->no-move :62, push-into-wall->no-move :68, push success :69-70, block-on-target->reward :76). Promotion of WorldModelPolicy only via the measurement protocol (REBUILD_PLAN.md:69-73): local 8/8 + push 3/3 + pytest green AND no held-out game regressed >0; reverts mandatory on regression.

## Risks
1. scene_key DRIFT from object_state_key would silently break predict-then-verify and graph unification — mitigated by sharing _object_tuples (one source of truth) + a dedicated equality test on real grids. This is the highest-leverage correctness risk. 2. C3 not ready / wrong affordances — mitigated by StubAffordanceModel for independent build, refuse-on-uncertainty default, and verify_step auto-disable in C7. 3. TOGGLE pairing unknown without C2/C5 — v1 emits the event but does NOT mutate the paired object (no overconfident door-open prediction); links() reserved for later. 4. NON-axis / non-rigid motion — predict works cell-wise from raw deltas; if no delta for an action -> refuse; occupancy gating not required by predict (only by C6's lattice planner). 5. Click semantics game-specific — v1 declines all clicks without a confident learned affordance, keeping click games (vc33, lp85, r11l) on the existing salience+graph path with zero risk. 6. CHAIN push / box-into-box — explicitly unsupported in v1: a second blocker triggers blocked/refuse rather than a wrong multi-push rollout (conservative; planner falls back to real exploration). 7. The lone subtle regression trap is the unknown-color DEFAULT: it must be REFUSE, never assume-passable (desyncs through real walls) and never assume-block (contradicts spatial.py optimism) — this is explicitly enforced before the BLOCK branch. 8. Deferred CNN forward model sits behind the same Prediction.known/valid gates so it cannot reintroduce overconfidence; out of scope for v1.
