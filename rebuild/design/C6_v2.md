# C6 v2 — Planner (REDESIGN: plan over the C4 forward model, not occupancy)

The previous two C6 attempts FAILED because the planner grounded on `spatial.py`'s
OccupancyMap, whose `.usable` requires BOTH movement axes — but the motion model often
learns only one axis per game (e.g. maze `{4:(0,9)}`, switchdoor `{2:(10,0)}`), so the
planner was 100% inert (0 plan actions emitted). Fix the DESIGN, not just bugs.

## Core design (forward-model search)

Plan by **searching over the C4 forward world model** (`forward_model.py`: `ForwardModel`
with `scene_from_grid`, `predict_move`/`predict_click`, `rollout`, `verify_step`), NOT over
occupancy. Concretely:

- **State for search** = a C4 `Scene` (object-level, hashable via `Scene.key()`), seeded by
  `scene_from_grid(grid)`.
- **Actions** = available simple actions (1..5) + a small set of salient clicks (reuse
  `perception.salient_click_targets`, top ~8).
- **Transition** = `ForwardModel.predict(scene, action)` (uses C3 affordances). Only expand
  predictions the model is CONFIDENT about (`verify_step`/reliable); treat unknown as a leaf.
- **Goal test** = the C5 goal hypothesis (`goals.py`): a predicted scene/transition that
  satisfies the inferred goal (e.g. a COLLECT object vanished, block delivered to GOAL,
  avatar on GOAL). If C5 has no hypothesis yet, plan toward the nearest **affordance-typed
  interaction** (COLLECT/TOGGLE/GOAL object) as a subgoal.
- **Search** = bounded BFS/A* over predicted scenes (cap nodes, e.g. 2000; depth, e.g. 40),
  heuristic = object-distance from avatar to the goal/subgoal object. Return the action
  sequence to the first goal-satisfying predicted scene.
- **Execution** = emit the plan actions one per `decide()` call; **re-plan** if the observed
  scene diverges from the predicted one (model error) — do NOT one-shot-latch per level.

## Hard requirements (acceptance)

1. **Not inert:** with the planner flag ON, it MUST emit > 0 plan actions and reach the
   goal test on at least the local games where a plan exists (collect, switchdoor, push,
   maze). Add a test asserting plan actions emitted > 0 on >=3 local games.
2. **No occupancy dependency for activation** — never gate planning on `occ.usable`. (May
   still use occupancy as an OPTIONAL obstacle hint inside the heuristic, never as a gate.)
3. **Default-OFF flag** (`ARCAGI3_PLANNER`), byte-identical OFF; integrate into
   `wm_policy.WorldModelPolicy` (consumed only when worldmodel+planner flags ON).
4. **No regression:** `uv run pytest` green; `reactive` 8/8 / 27 levels / push 3/3 unchanged.
5. Use the venv (`uv run`) for all verification.

## Plug-in point

`wm_policy.WorldModelPolicy`: when planner ON and a plan exists for the current scene,
return the next planned action; else fall back to the existing explore/navigate/graph path.
Re-plan on divergence or when the plan is exhausted without reward.
