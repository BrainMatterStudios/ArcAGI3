ARC Prize 2026 · internal research dossier · 2026-07-14

Verification-by-execution works with a local, offline brain. The leap the campaign was searching for is real.

For weeks the working belief was that our base agent (the "duck," 1.26) sat near the method-class frontier and every lever was a random walk. That belief rested on a scaffold gap, not a capability ceiling. We ported a released executable-world-model loop onto our own offline engine, replaced its frontier coding agent with a local one, hid the game identity behind a firewall — and it solved genuinely hard games from frames alone.

a game frame is a 64×64 grid of colors 0–15 — discrete, deterministic, and exactly checkable. that is what makes a proposed world-model verifiable.

The method, in four verifiable parts

  • probe

    Act a little, record the frames

    Take a few real actions; the engine returns settled 64×64 frames. Real actions are the costly, quadratically-scored resource — exploration is minimized.

  • model

    Write an executable world model

    The brain writes Python: a transition engine, a state reconstructor, and a renderer that must reproduce the observed frame exactly.

  • verify

    Check it against reality, pixel-exact

    The harness replays every recorded attempt through the model and asserts the rendered frames match. A wrong model is rejected mechanically — no trust required.

  • plan

    Search the certified model, then execute

    Planning happens inside the verified model (free). Only the final plan is executed in the real game — few actions, high efficiency.

Because nothing is fit to the dev set — the model is verified against each game's own frames at runtime — the approach is immune to the dev≠hidden gap that killed every prior lever.

What's proven vs. what remains

  1. Capability proven

    A non-frontier-hosted brain drives the loop to ~25/100 on hard games, offline, on our stack, frames-only, with honest failure behavior. This was the one decisive open question. It is answered.

  2. A local model must drive the coding loop offline open

    At eval there is no Claude. The brain that reads frames, edits the model, and runs the verifier must be a local model (Qwen-27B / gpt-oss-120B) via a custom agent loop. Buildable; the structure is validated.

  3. Is a local model strong enough? open · key risk

    Claude Opus drove these. A 27B local model is weaker at agentic coding. Testable — cheaply floor-tested on-host via MLX, faithfully on one free Kaggle GPU.

  4. Fit 9 hours, 110 games, one GPU open

    ~283k tokens/game is ~20–40× the uniform budget. The answer is selective execution: cheap-probe all, time-box the loop, bank the cracks, duck-baseline the rest. Conservative math still lands ~3–5× the field leader.
